# 文档来源筛选设计

## 目标

在知识体系文档页中按摄入 Source 筛选文档。用户选择一个没有文档的 Source 时，列表应为空，而不是显示其他 Source 的文档。

## 用户界面

- 保留“上传来源”选择器，只决定新上传文档的归属。
- 新增独立的“来源筛选”选择器，提供“所有来源”和当前知识体系的 Source。
- 所有有权读取文档的用户都可以筛选；只有有写权限的用户可以选择上传来源。
- 来源筛选与虚拟文件夹、文件名搜索、解析状态和分页组合。筛选后总数及页码以服务端筛选结果为准；切换 Source 时回到第一页。
- 虚拟文件夹导航仍是独立维度，其目录列表不因 Source 筛选而重写。

## API 与查询语义

- 文档分页 API 增加可选 `source_id` 查询参数；省略时保持当前行为。
- `source_id` 必须属于当前知识体系；无效或跨知识体系的 ID 返回客户端错误，不返回其他知识体系的数据。
- 选择 Source 时，文档匹配主归属 `Document.SourceId`，或存在指向该文档的 `SourceDocumentBinding`。`Any` 条件用于避免绑定造成重复文档行。
- Source、虚拟文件夹、搜索文本和解析状态条件在数据库分页与总数统计前组合。选择没有匹配文档的 Source 时返回空 `items` 和 `total = 0`。
- “所有来源”不附加 Source 条件，因此仍包含没有 Source 归属的文档。

## 验收

- 后端分页测试：Source A 的筛选不返回 Source B 文档；绑定到所选 Source 的共享文档可见且不重复；空 Source 返回零条；非法或跨 KS Source 被拒；Source 与文件夹、搜索、状态组合后 `items`、`total` 一致。
- 浏览器测试：准备一个归属其他 Source 的文档，选择空的“测试”Source 后确认文档行消失且空状态显示；切回“所有来源”后文档恢复。确认上传来源选择仍独立控制上传目标，文件夹导航行为不变。
- 现有无 `source_id` 的文档分页请求和上传来源行为保持兼容。

## 非目标

- 不改变 Source 与虚拟文件夹的领域关系。
- 不把客户端当前页过滤当作实现；该方式会导致总数和分页不正确。
- 不实现或开放任何新的连接器。

本设计仅调整文档浏览与筛选路径。
